# Setup a Jupyter Notebook

The purpose of this tutorial is to help researchers who is not familiar with Jupyter Notebook and want to use Workbench to submit a task to the TES endpoint.
Once familiar with Jupyter Notebook, you can use it to submit a task to the TES endpoint, retrieve the results, and use the results in your analysis in one place.

## Steps

<Steps>

### Install Python

The Workbench requires **Python 3.13 or newer**. Check whether you already have it:

```sh copy
python3 --version
```

If the command is not found, or reports a version below 3.13, install it.

<Tabs items={["macOS", "Windows", "Linux"]}>
<Tabs.Tab title="macOS">

Download the installer from [python.org/downloads](https://www.python.org/downloads/) and run it, or use [Homebrew](https://brew.sh/):

```sh copy
brew install python@3.13
```

</Tabs.Tab>
<Tabs.Tab title="Windows">

Download the installer from [python.org/downloads](https://www.python.org/downloads/).

<Callout type="warning">
  On the first screen of the installer, tick **Add python.exe to PATH** before
  clicking Install. Without it, Windows will not find the `python` command in
  the terminal.
</Callout>

Use `python` instead of `python3` in the commands below, and run them in **PowerShell**.

</Tabs.Tab>
<Tabs.Tab title="Linux">

On Debian or Ubuntu:

```sh copy
sudo apt update
sudo apt install python3.13 python3.13-venv
```

</Tabs.Tab>
</Tabs>

### Create a project folder

Everything for your analysis lives in one folder: your notebooks, your `config.yml`, and the `output/` folder the Workbench downloads results into.

```sh copy
mkdir my-5s-tes-analysis
cd my-5s-tes-analysis
```

Keep this terminal open — the remaining commands all run from inside this folder.

### Create a virtual environment

A virtual environment is a private copy of Python for this project. It keeps the Workbench and its dependencies separate from anything else on your machine, so upgrading one project can never break another.

<Tabs items={["macOS / Linux", "Windows (PowerShell)", "uv"]}>
<Tabs.Tab title="macOS / Linux">

```sh copy
python3 -m venv .venv
source .venv/bin/activate
```

</Tabs.Tab>
<Tabs.Tab title="Windows (PowerShell)">

```powershell copy
python -m venv .venv
.venv\Scripts\Activate.ps1
```

If PowerShell blocks the activation script, allow it for the current session and try again:

```powershell copy
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

</Tabs.Tab>
<Tabs.Tab title="uv">

[uv](https://docs.astral.sh/uv/) is a faster alternative to `pip` and `venv`. If you have it installed:

```sh copy
uv venv --python 3.13
source .venv/bin/activate
```

</Tabs.Tab>
</Tabs>

Your terminal prompt now starts with `(my-5s-tes-analysis)`, which tells you the environment is active.

### Install the Workbench and JupyterLab

JupyterLab is the application that runs in your browser and lets you create and run notebooks.

<Tabs items={["pip", "uv"]}>
<Tabs.Tab title="pip">

```sh copy
pip install five-safes-tes-workbench jupyterlab
```

</Tabs.Tab>
<Tabs.Tab title="uv">

```sh copy
uv pip install five-safes-tes-workbench jupyterlab
```

</Tabs.Tab>
</Tabs>

### Start JupyterLab

```sh copy
jupyter lab
```

This starts a small web server on your own machine and opens JupyterLab in your browser at `http://localhost:8888`. Nothing is uploaded anywhere — the notebook runs locally and only talks to the Submission layer when you call `wb.submit()` or `wb.fetch_outputs()`.

<Callout type="info">
  Leave the terminal running while you work; closing it stops the notebook
  server. When you have finished, return to the terminal and press `Ctrl` + `C`
  to shut it down.
</Callout>

### Create a notebook and check the installation

In the JupyterLab file browser you will see your project folder. Under **Notebook** in the launcher, click **Python 3 (ipykernel)** to create a new notebook, then rename it to something like `analysis.ipynb`.

Type the following into the first cell and press `Shift` + `Enter` to run it:

```python copy
from five_safes_tes_workbench.workbench import Workbench

wb = Workbench()
print("Workbench ready")
```

If you see `Workbench ready` underneath the cell, your environment is set up correctly and you can move on to [use the Workbench to submit an analysis](/tutorials/submit-to-5s-tes/workbench).

<Callout type="warning">
  - If this cell raises `ModuleNotFoundError`, JupyterLab is almost certainly
  running against a different Python than the one you installed into. Close it,
  check your prompt still shows `(my-5s-tes-analysis)`, reinstall with the command in step 4,
  and start `jupyter lab` again from the same terminal. 
  
  - If you already activated the virtual environment, but have the error `command not found: jupyter` 
  when starting JupyterLab, try step 4 again to re-install JupyterLab.
</Callout>

</Steps>

<Callout>
  - Rather than starting from an empty notebook, you can download the [example
  notebook](https://github.com/federated-research/5S-TES-Workbench/blob/main/src/five_safes_tes_workbench/notebooks/workbench-example.ipynb)
  into your project folder and open it in JupyterLab. It contains ready-to-run
  cells for every step to submit a task to the TES endpoint and retrieve the
  results.
  
  - Follow steps above once. Afterwards you only need to follow steps below to start working again.

```sh copy
cd my-5s-tes-analysis  # move to your project folder
source .venv/bin/activate  # activate your virtual environment
jupyter lab  # start JupyterLab
```

</Callout>
